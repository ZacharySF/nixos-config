# nixos-config

Declarative configuration for the external (`xelo-nixos`) and internal (`xelo-nixos-main`) NixOS installations, built as a
**Nix flake** with **home-manager** wired in as a NixOS module.

On the **internal drive** (`xelo-nixos-main`), rebuild the system and user environment with:

```sh
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos-main
```

The short command is `rebuild`; `rebuild-check` builds without activation.
`#xelo-nixos` is **only for the external installation**: it has different root,
boot, and swap UUIDs. Applying it on the internal drive caused the September 24,
2026 emergency-mode failure. The shared boot module now checks the mounted root
and boot UUIDs before activation or bootloader changes.

Choosing an older generation in the boot menu recovers that boot, but does not
reset the saved system profile or default boot entry. After booting the internal
installation successfully, run the explicit `xelo-nixos-main` command above to
make the corrected configuration the default.

---

## 1. Why it looks like this

The old setup had four half-finished copies of the config in `~/.dotfiles`,
`/etc/nixos`, `/etc/nixos/.dotfiles`, and a separate standalone home-manager in
`~/.config/home-manager`. `/etc/nixos/configuration.nix` had  errors and
would not build. 
Design rules:

- **Flake** → inputs are pinned in `flake.lock`, so
  the machine is reproducible and moving to a new laptop is a `git clone` + one
  command.
- **home-manager as a NixOS module** → no separate `home-manager switch`; the
  system rebuild does everything.
- **Split by topic, not by giant file** → every file is short and owns one
  concern.

## 2. Layout

```
flake.nix                     inputs + both nixosConfigurations
flake.lock                    pinned versions of every input (commit this)

hosts/
  xelo-nixos-main/             internal NVMe installation, alongside Windows
    default.nix               hostname, UID, zram, small shared ESP settings
    hardware-configuration.nix internal filesystem and swap UUIDs
  xelo-nixos/
    default.nix               machine-specific: hostname, stateVersion, imports
    hardware-configuration.nix generated by nixos-generate-config (disks/CPU)

modules/system/               everything that needs root / affects all users
  default.nix                 imports all of the below
  nix.nix                     nix daemon settings, garbage collection, unfree
  boot.nix                    bootloader, kernel, firmware
  locale.nix                  timezone, locale, keymap
  networking.nix              NetworkManager, Bluetooth, SSH, AmneziaVPN, firewall
  audio.nix                   PipeWire
  desktop.nix                 Niri compositor + greetd login + portals + fonts
  users.nix                   user accounts, docker, nix-ld
  packages.nix                the short list of system-wide packages
  wispr-flow.nix              Wispr Flow dictation + its uinput/input udev rule

pkgs/wispr-flow/              Wispr Flow package (unofficial Linux port's AppImage)

home/                         everything inside /home/xelo (home-manager)
  default.nix                 imports all of the below
  shell.nix                   bash, prompt, core CLI tools, direnv
  git.nix                     git identity + gh   <-- only personal data in repo
  desktop.nix                 GTK theme, cursor, XDG user dirs
  niri/
    default.nix               installs config.kdl + Niri helper tools
    config.kdl                the actual Niri config (raw KDL, hand-editable)
  foot.nix                    terminal emulator (colours in Nix)
  quickshell.nix              Quickshell bar service and 30-pixel height
  quickshell/                 vendored nunera/quickshell-bar QML
  skwd-theme/                 app colours follow the skwd-wall wallpaper palette
    default.nix               integrations, reload hooks, fallbacks, config.json merge
    templates/                colour-only templates (copied once into skwd-wall)
  btop.nix                    system monitor config
  editors.nix                 zed / vscode / obsidian
  zed/settings.json           zed config (raw)
  dev.nix                     quant + computer-architecture toolchain
  spicetify.nix               Spotify theming
```

### How the imports chain together

```
flake.nix
 └─ hosts/<selected-host>/default.nix
     ├─ hardware-configuration.nix
     └─ modules/system/default.nix  ──► nix, boot, locale, networking,
     │                                   audio, desktop, users, packages
     └─ (home-manager module from flake.nix)
         └─ home/default.nix        ──► shell, git, niri, desktop, foot,
                                          quickshell, btop, editors, dev, spicetify
```

## 3. The machine, in one paragraph

Intel laptop. Boots via systemd-boot, latest kernel. `greetd` uses `tuigreet`
to prompt for credentials and start a **Niri** (scrollable-tiling Wayland) session.
The session pieces are separate programs: **Quickshell** (bar), **fuzzel**
(launcher, `Mod+Tab`), **mako** (notifications), **hyprlock** (`Super+Alt+L`),
**WezTerm** (terminal, `Mod+Return`), **swaybg** (wallpaper). Audio is PipeWire,
networking is NetworkManager, Bluetooth is on. Docker is enabled. `nix-ld` lets
non-Nix binaries run. Firewall is default-deny.

New interactive Bash shells show Fastfetch with the configured image.
`home/shell.nix` selects `kitty-direct` graphics when `TERM_PROGRAM=tern`;
other terminals retain the iTerm image protocol in `home/fastfetch.jsonc`.

Full Niri keybindings: press `Mod+Shift+/` in the session, or read
`home/niri/config.kdl` (it is mostly the upstream default with a few tweaks —
startup apps, keyboard repeat rate, `Mod+T` → Firefox, `Mod+B` → bluetooth menu).

## 4. Everyday use

| Task | Command (aliases defined in `home/shell.nix`) |
|---|---|
| Apply config changes | `rebuild` |
| Activate temporarily; next boot uses the saved default | `rebuild-test` |
| Just check it builds, don't touch system | `rebuild-check` |
| Update nixpkgs / home-manager | `update` then `rebuild` |
| Update only OMP | `nix flake update oh-my-pi --flake ~/nixos-config` then `rebuild` |
| Roll back | reboot → pick previous generation in the boot menu, **or** `sudo nixos-rebuild switch --rollback` |
| Format nix files | `nixfmt` |
| Free unreferenced store paths, retaining generations | `nix-collect-garbage` (older generations are pruned weekly) |

OMP is pinned to **18.14.1** (upstream revision
`c29f7c56f5530d805bb2887ade964aa55970d8e1`) in `flake.lock`.
After updating only its input, use `rebuild-check` to build the complete
`xelo-nixos-main` configuration without activation, then `rebuild` when ready
to activate it. The running `omp --version` changes only after activation.

To change something, edit the relevant file under `modules/` or `home/`, then
`rebuild`. Commit afterwards.

### Wispr Flow dictation

The package pins Wispr Flow **1.6.1209**, Linux packaging **1.0.5**, and helper
**0.1.3**. The helper discovers keyboards connected after startup and avoids
leaving modifiers stuck after paste. The configured push-to-talk shortcut is
**Left Ctrl + Left Alt**.

`pkgs/wispr-flow/niri-terminal-paste.patch` uses niri's read-only `FocusedWindow`
socket request at paste time: known terminals receive **Ctrl+Shift+V**; other
applications keep **Ctrl+V**. It does not change niri configuration or terminal
keybindings. The pinned helper build runs its regression suite, including the
terminal/non-terminal and missing-focus cases.

For an app-only update without activating the rest of NixOS, build the package
with the flake's pinned nixpkgs and install the resulting store path with
`nix profile add`. This user-profile copy takes precedence over the system copy.
After a normal system rebuild includes the same repair, remove that temporary
copy with `nix profile remove wispr-flow` so future system updates take effect.

### Tern terminal and transparency

`pkgs/tern/default.nix` packages the supplied **0.9.8** Linux x86_64 archive,
patches its native library paths, and supplies `gdbus` for desktop portals.
Import the closed-beta download before building:

```sh
nix-store --add-fixed sha256 ~/downloads/Tern-0.9.8-linux-x86_64.tar.gz
```

The launcher defaults **only Tern** to `WGPU_BACKEND=vulkan`. On this Intel
laptop its default OpenGL renderer reports “no transparent swapchain” and
ignores background transparency. An explicit `WGPU_BACKEND` still overrides
the package default. The Niri rule for `so.stencil.tern` blurs behind the
window, removes the opaque focus-ring backing, and uses 12px rounded corners.
It does not lower whole-window opacity, so text stays opaque.

Tern keeps editable appearance preferences in `~/.config/tern/settings.json`.
The applied look uses `dark-catppuccin`, the `Float` interface layout, Clear
material, opacity `50`, JetBrainsMono Nerd Font at `14`, line-height adjustment
`12%`, padding `18` horizontally and `14` vertically, and pane headers only
when split. The original preferences are backed up beside it as
`settings.before-appearance.json`.

For an app-only update, build this package with the pinned nixpkgs and install
its store path with `nix profile add`; existing launchers should use the packaged
`tern`, not the original Downloads binary. Upgrades are managed through Nix
because the package store is read-only. Appearance settings remain user-editable.

### Quickshell bar

- Click the speaker for output/input devices and application mixers.
- Middle-click or right-click the speaker to toggle output mute.
- Scroll the speaker to change output volume in 5% steps, capped at 100%.
- Click network status for Wi-Fi and Bluetooth controls.
- Click the battery for charge estimates, health and charge history.
- The application dot opens Fuzzel.
- The GitHub icon replaces the workspace strip and opens https://github.com/zacharysf.
- Bluetooth status and the Blueman tray button are hidden; Bluetooth controls remain in the network popup.

The bar is vendored from [nunera/quickshell-bar](https://github.com/nunera/quickshell-bar)
at revision `a6787668c2deb891e59a7eea0140aa7dc8f7d1c4`.
`home/quickshell.nix` sets its height to 25 logical pixels (upstream: 34),
with uniform 16-pixel icons, 12-pixel text and a 6-pixel screen-edge gap;
the battery percentage stays visible beside its icon. No Steam launcher or
package is added. The launcher opens Fuzzel; mako continues handling notifications.
Host-specific upstream scratchpad, tablet, display-layout and power-profile
controls are omitted because their helper services are not installed here.

Edit `home/quickshell/` and rebuild. Home Manager restarts the bar when QML
changes; palette and geometry changes are watched live. Restart manually with:

```sh
systemctl --user restart quickshell-bar.service
```

Run the battery label regression with:

```sh
BAR_NOTIFICATIONS=0 qs -p home/quickshell/battery-check.qml
```

### Wallpaper-driven colours (skwd-wall)

Each time skwd-wall applies a wallpaper it renders the templates registered in
`~/.config/skwd-wall-v2/config.json` → `integrations` into
`~/.local/state/skwd-theme/` (btop: `~/.config/btop/themes/skwd-managed.theme`).
The Nix-managed configs of Quickshell, Niri, WezTerm, mako, fuzzel, foot and btop
include those files; reload hooks live in `~/.config/skwd-theme/hooks/`.

- Live: Quickshell, Niri focus ring, WezTerm, btop, mako. Next open: fuzzel, foot.
- `gtk-mode` sets GTK4/libadwaita light/dark from the palette; GTK3 stays Adwaita-dark.
- Templates are copied into `~/.config/skwd-wall-v2/matugen/templates/` only if
  missing, so edits there survive rebuilds; delete one to get the repo version back.
- Activation adds missing integrations, replaces the managed Quickshell entry,
  and retires Ironbar. Other integrations and saved wallpaper profiles are preserved.
- Re-render without changing wallpaper: `skwd-helm retheme`.
- Quickshell watches its palette JSON and applies changes without a reload hook.

### Transparent Firefox

`home/desktop.nix` manages the default profile's Linux transparency preferences,
`userChrome.css`, `userContent.css`, and the hash-pinned Zen Internet 3.2.0 add-on.
The active profile is `~/.mozilla/firefox/default`. Keep **System theme — auto**
enabled; opaque themes cover the glass effect. Restart Firefox after changing CSS.
Adjust `--ft-tint` in `userChrome` to change the current 35% dark tint.

Zen Internet is pinned to the toolbar. Its runtime settings and downloaded styles
remain in the profile rather than being reset on each rebuild: **Global Styling**,
**Auto Update**, and **Force Styling** are enabled. On a new profile, click
**Refetch latest styles** once and enable Force Styling. Use **Skip Forcing for
this Site** if a website becomes unreadable. The older Transparent Zen add-on was
disabled, not deleted, to avoid conflicting styles.

`home/niri/config.kdl` enables native background blur for Firefox only, with
`draw-border-with-background false` so the focus ring does not fill the window.
This uses niri 26.04's built-in blur; no compositor fork or whole-window opacity
rule is needed, so text and images stay opaque. Firefox's restricted pages
(including Settings, AMO, and the PDF viewer) are not restyled by the add-on.

The pre-change preferences and desktop configuration are backed up under
`~/.local/state/firefox-transparency-backup/20261016-134443/`.

## 5. Per-project dev environments

`dev.nix` gives you a solid global toolchain (C/C++, Rust via `rustup`, a Python
scientific stack, Verilator/Yosys/GTKWave, QEMU). For anything project-specific,
**don't** add to `dev.nix` — use a project flake instead:

```sh
cd my-project
nix flake init -t github:nix-community/nix-direnv   # or write flake.nix by hand
echo "use flake" > .envrc && direnv allow
```

`direnv` + `nix-direnv` are already enabled, so the project's toolchain loads
when you `cd` in and unloads when you leave. This keeps global state small and
each project reproducible on its own.

## 6. First-time setup on THIS machine (migrating off the old config)

```sh
# 1. build without switching, to be sure
rebuild-check

# 2. switch
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos-main

# 3. one-time per-user bits (not managed by Nix on purpose)
rustup default stable
gh auth login
# Wallpaper is installed automatically at ~/Pictures/wallpaper.jpg and ~/.config/background.

# 4. clean up the old scattered config (optional, after you've confirmed
#    the new setup works and rebooted once):
sudo rm -rf /etc/nixos/.dotfiles
rm -rf ~/.dotfiles ~/.config/home-manager
nix-channel --remove home-manager && rm -f ~/.nix-channels
rm -f ~/.gitconfig ~/.bashrc.backup          # now managed by home-manager
rm -rf ~/.local/zed.app ~/.local/bin/zed     # replaced by the Nix zed-editor
#   /etc/nixos/configuration.nix is now unused (flake builds ignore it) — you
#   can leave it or delete it.
```

Passwords are not in the repo. `xelo` already has one; set `aibox`'s with
`sudo passwd aibox` only if you want to log in as that sandbox user.

## 7. Migrating to a NEW machine

```sh
# on the new machine, after installing NixOS and getting online:
nix-shell -p git --run 'git clone https://github.com/ZacharySF/nixos-config ~/nixos-config'

# This example intentionally replaces the EXTERNAL host definition.
# For a separate machine, create a new host and flake output instead.
# Regenerate the hardware file for the selected host:
sudo nixos-generate-config --show-hardware-config \
  > ~/nixos-config/hosts/xelo-nixos/hardware-configuration.nix

# adjust hosts/xelo-nixos/default.nix if the hostname should change,
# then build:
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos
```

Then repeat the "one-time per-user bits" from section 6, and restore anything
that is deliberately outside version control (next section).

### Internal drive alongside Windows

`hosts/xelo-nixos-main` preserves the internal installation's filesystem UUIDs,
Intel NPU support, and `xelo` UID 1001. It uses only internal swap. Both hosts
share the desktop and wallpaper. On the internal installation use:

```sh
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos-main
```

Its shell aliases derive their target from the NixOS host. The shared Windows ESP has a
five-second systemd-boot menu with at most two NixOS generations. Firmware boot
order is preserved. Choose the internal WD drive in the firmware boot menu;
systemd-boot detects Windows Boot Manager on the same ESP.

## 8. What is deliberately NOT in this repo

Version control here = your *configuration*, not your *data* or *secrets*:

- SSH keys (`~/.ssh`) — none currently exist; generate with `ssh-keygen` per machine
- `gh` / GitHub tokens — stored by gnome-keyring after `gh auth login`
- AmneziaVPN server configs / credentials (`~/.config/AmneziaVPN.ORG`) — import in the app
- Browser profiles, Obsidian vault contents, Spotify login
- The `~/axon` project (its own git repo) and `~/axon-images`
- `*.qcow2` VM images

If you later want encrypted secrets *in* the repo, add
[sops-nix](https://github.com/Mic92/sops-nix) or
[agenix](https://github.com/ryantm/agenix) as a flake input.

## 9. Updating

```sh
update          # nix flake update  — bumps flake.lock to latest nixpkgs etc.
rebuild-check   # make sure it still builds
rebuild         # apply
git commit -am "flake update $(date +%F)"
```

If an update breaks something, `git checkout flake.lock` and `rebuild` puts you
back.

## Saved desktop files

`home/` contains the current Home Manager configuration, including Niri, Quickshell,
Foot, shell, GTK, Fastfetch, and Zed settings. `home/wallpaper/wallpaper.jpg` is
installed at both original wallpaper paths. The root `configuration.nix` and
`.dotfiles/` and `legacy/home/` preserve the older configuration for reference; use the root flake
for builds and updates.

The `xelo-nixos` host describes the external drive; `xelo-nixos-main` describes
the internal drive. Always select the host matching the installation.
