# nixos-config

Declarative configuration for the external (`xelo-nixos`) and internal (`xelo-nixos-main`) NixOS installations, built as a
**Nix flake** with **home-manager** wired in as a NixOS module.

system + user enviornment

```sh
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos
```

---

## 1. Why it looks like this

The old setup had four half-finished copies of the config in `~/.dotfiles`,
`/etc/nixos`, `/etc/nixos/.dotfiles`, and a separate standalone home-manager in
`~/.config/home-manager`. `/etc/nixos/configuration.nix` had  errors and
would not build. 
Design rules:

- **Flake** → inputs are pinned in `flake.lock`, so
  the machine is reproducible and moving to a new laptop is a `git clone` + one
  command.
- **home-manager as a NixOS module** → no separate `home-manager switch`; the
  system rebuild does everything.
- **Split by topic, not by giant file** → every file is short and owns one
  concern.

## 2. Layout

```
flake.nix                     inputs + the single nixosConfiguration "xelo-nixos"
flake.lock                    pinned versions of every input (commit this)

hosts/
  xelo-nixos/
    default.nix               machine-specific: hostname, stateVersion, imports
    hardware-configuration.nix generated by nixos-generate-config (disks/CPU)

modules/system/               everything that needs root / affects all users
  default.nix                 imports all of the below
  nix.nix                     nix daemon settings, garbage collection, unfree
  boot.nix                    bootloader, kernel, firmware
  locale.nix                  timezone, locale, keymap
  networking.nix              NetworkManager, Bluetooth, SSH, AmneziaVPN, firewall
  audio.nix                   PipeWire
  desktop.nix                 Niri compositor + greetd login + portals + fonts
  users.nix                   user accounts, docker, nix-ld
  packages.nix                the short list of system-wide packages

home/                         everything inside /home/xelo (home-manager)
  default.nix                 imports all of the below
  shell.nix                   bash, prompt, core CLI tools, direnv
  git.nix                     git identity + gh   <-- only personal data in repo
  desktop.nix                 GTK theme, cursor, XDG user dirs
  niri/
    default.nix               installs config.kdl + Niri helper tools
    config.kdl                the actual Niri config (raw KDL, hand-editable)
  foot.nix                    terminal emulator (colours in Nix)
  ironbar.nix                 status bar (raw config.json/style.css + battery script)
  ironbar/                    those raw files
  btop.nix                    system monitor config
  editors.nix                 zed / vscode / obsidian
  zed/settings.json           zed config (raw)
  dev.nix                     quant + computer-architecture toolchain
  spicetify.nix               Spotify theming
```

### How the imports chain together

```
flake.nix
 └─ hosts/xelo-nixos/default.nix
     ├─ hardware-configuration.nix
     └─ modules/system/default.nix  ──► nix, boot, locale, networking,
     │                                   audio, desktop, users, packages
     └─ (home-manager module from flake.nix)
         └─ home/default.nix        ──► shell, git, niri, desktop, foot,
                                          ironbar, btop, editors, dev, spicetify
```

## 3. The machine, in one paragraph

Intel laptop. Boots via systemd-boot, latest kernel. `greetd` logs `xelo`
straight into a **Niri** (scrollable-tiling Wayland) session — no GNOME/KDE.
The session pieces are separate programs: **ironbar** (bar), **fuzzel**
(launcher, `Mod+D`), **mako** (notifications), **swaylock** (`Super+Alt+L`),
**foot** (terminal, `Mod+Return`), **swaybg** (wallpaper). Audio is PipeWire,
networking is NetworkManager, Bluetooth is on. Docker is enabled. `nix-ld` lets
non-Nix binaries run. Firewall is default-deny.

Full Niri keybindings: press `Mod+Shift+/` in the session, or read
`home/niri/config.kdl` (it is mostly the upstream default with a few tweaks —
startup apps, keyboard repeat rate, `Mod+T` → Firefox, `Mod+B` → bluetooth menu).

## 4. Everyday use

| Task | Command (aliases defined in `home/shell.nix`) |
|---|---|
| Apply config changes | `rebuild` |
| Test changes, auto-revert on reboot | `rebuild-test` |
| Just check it builds, don't touch system | `rebuild-check` |
| Update nixpkgs / home-manager | `update` then `rebuild` |
| Roll back | reboot → pick previous generation in the boot menu, **or** `sudo nixos-rebuild switch --rollback` |
| Format nix files | `nixfmt` |
| Free disk space | happens weekly automatically; force with `nix-collect-garbage -d` |

To change something, edit the relevant file under `modules/` or `home/`, then
`rebuild`. Commit afterwards.

## 5. Per-project dev environments

`dev.nix` gives you a solid global toolchain (C/C++, Rust via `rustup`, a Python
scientific stack, Verilator/Yosys/GTKWave, QEMU). For anything project-specific,
**don't** add to `dev.nix` — use a project flake instead:

```sh
cd my-project
nix flake init -t github:nix-community/nix-direnv   # or write flake.nix by hand
echo "use flake" > .envrc && direnv allow
```

`direnv` + `nix-direnv` are already enabled, so the project's toolchain loads
when you `cd` in and unloads when you leave. This keeps global state small and
each project reproducible on its own.

## 6. First-time setup on THIS machine (migrating off the old config)

```sh
# 1. build without switching, to be sure
rebuild-check

# 2. switch
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos

# 3. one-time per-user bits (not managed by Nix on purpose)
rustup default stable
gh auth login
# Wallpaper is installed automatically at ~/Pictures/wallpaper.jpg and ~/.config/background.

# 4. clean up the old scattered config (optional, after you've confirmed
#    the new setup works and rebooted once):
sudo rm -rf /etc/nixos/.dotfiles
rm -rf ~/.dotfiles ~/.config/home-manager
nix-channel --remove home-manager && rm -f ~/.nix-channels
rm -f ~/.gitconfig ~/.bashrc.backup          # now managed by home-manager
rm -rf ~/.local/zed.app ~/.local/bin/zed     # replaced by the Nix zed-editor
#   /etc/nixos/configuration.nix is now unused (flake builds ignore it) — you
#   can leave it or delete it.
```

Passwords are not in the repo. `xelo` already has one; set `aibox`'s with
`sudo passwd aibox` only if you want to log in as that sandbox user.

## 7. Migrating to a NEW machine

```sh
# on the new machine, after installing NixOS and getting online:
nix-shell -p git --run 'git clone https://github.com/ZacharySF/nixos-config ~/nixos-config'

# regenerate the hardware file for the new hardware:
sudo nixos-generate-config --show-hardware-config \
  > ~/nixos-config/hosts/xelo-nixos/hardware-configuration.nix

# adjust hosts/xelo-nixos/default.nix if the hostname should change,
# then build:
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos
```

Then repeat the "one-time per-user bits" from section 6, and restore anything
that is deliberately outside version control (next section).

### Internal drive alongside Windows

`hosts/xelo-nixos-main` preserves the internal installation's filesystem UUIDs,
Intel NPU support, and `xelo` UID 1001. It uses only internal swap. Both hosts
share the desktop and wallpaper. On the internal installation use:

```sh
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos-main
```

Its shell aliases select this host automatically. The shared Windows ESP has a
five-second systemd-boot menu with at most two NixOS generations. Firmware boot
order is preserved. Choose the internal WD drive in the firmware boot menu;
systemd-boot detects Windows Boot Manager on the same ESP.

## 8. What is deliberately NOT in this repo

Version control here = your *configuration*, not your *data* or *secrets*:

- SSH keys (`~/.ssh`) — none currently exist; generate with `ssh-keygen` per machine
- `gh` / GitHub tokens — stored by gnome-keyring after `gh auth login`
- AmneziaVPN server configs / credentials (`~/.config/AmneziaVPN.ORG`) — import in the app
- Browser profiles, Obsidian vault contents, Spotify login
- The `~/axon` project (its own git repo) and `~/axon-images`
- `*.qcow2` VM images

If you later want encrypted secrets *in* the repo, add
[sops-nix](https://github.com/Mic92/sops-nix) or
[agenix](https://github.com/ryantm/agenix) as a flake input.

## 9. Updating

```sh
update          # nix flake update  — bumps flake.lock to latest nixpkgs etc.
rebuild-check   # make sure it still builds
rebuild         # apply
git commit -am "flake update $(date +%F)"
```

If an update breaks something, `git checkout flake.lock` and `rebuild` puts you
back.

## Saved desktop files

`home/` contains the current Home Manager configuration, including Niri, Ironbar,
Foot, shell, GTK, Fastfetch, and Zed settings. `home/wallpaper/wallpaper.jpg` is
installed at both original wallpaper paths. The root `configuration.nix` and
`.dotfiles/` and `legacy/home/` preserve the older configuration for reference; use the root flake
for builds and updates.

The `xelo-nixos` host describes the external drive; `xelo-nixos-main` describes
the internal drive. Always select the host matching the installation.
