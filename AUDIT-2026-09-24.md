# Rebuild failure audit — September 24, 2026

The failure came from activating the external-drive host on the internal-drive
installation. The build succeeded; changing the required filesystems caused
systemd to enter emergency mode and stop the desktop session.

## Evidence

All times below are local (America/Matamoros, UTC−05:00), from `journalctl -b -1`.

| Time | Event |
|---|---|
| 02:20:42 | `sudo nixos-rebuild switch --flake /home/xelo/nixos-config#xelo-nixos-main` |
| 02:20:57 | Correct generation 109 activation completed |
| 02:21:27 | `sudo nixos-rebuild switch --flake /home/xelo/nixos-config#xelo-nixos` |
| 02:21:42 | Internal disk swap and zram were deactivated |
| 02:21:43 | `/boot` was unmounted |
| 02:23:13 | Timed out waiting for external ESP UUID `286E-38B2` |
| 02:24:43 | External ESP and swap timed out; local filesystems failed; user session stopped |
| 02:24:45 | Emergency shell started |

The root and boot mounts currently match `hosts/xelo-nixos-main/hardware-configuration.nix`.
Generation 110's generated fstab instead references the external installation's
root, ESP, and swap UUIDs. There was no kernel panic, GPU hang, or OOM message
in the journal during this activation window.

At inspection, `/run/current-system` and `/run/booted-system` pointed to generation
109, but `/nix/var/nix/profiles/system` and `bootctl status` still selected generation
110 as the persistent default. Selecting generation 109 at boot recovered the
session without repairing that default.

## Changes prepared

- `README.md`: lead with the internal host command; explain the two installations,
  recovery, and the difference between a temporary activation and the saved boot
  default. Correct stale desktop descriptions and destructive cleanup advice.
- `home/shell.nix`: derive the three rebuild aliases from `osConfig.networking.hostName`.
  The previous internal aliases were already correct because of host overrides;
  this removes the misleading external default and duplicated overrides.
- `modules/system/boot.nix`: compare mounted `/` and `/boot` UUIDs with the selected
  host before activation or bootloader installation. Both hosts remain buildable.
  Fresh installation chroots without `/run/current-system` skip this runtime check.
- `modules/system/desktop.nix`: mask the speech-dispatcher socket as well as its
  service. Logs showed the remaining socket failing because its service was masked.
- `hosts/xelo-nixos-main/default.nix`: restrict ESP permissions to root using
  `fmask=0077,dmask=0077`, resolving bootctl's world-readable random-seed warning.

The pre-switch guard belongs to newly built generations; it cannot protect older
generations. Nixos-rebuild can update the system profile before this guard runs,
so a rejected switch should still be followed by a correct-host rebuild to restore
the profile. The guard prevents the service and bootloader changes that caused
this incident. It is designed for these two UUID-based ext4 installations.

## Other findings

- **AirPods volume policy:** `modules/system/audio.nix` checks every three seconds
  and unmutes/sets volume to 60% whenever the sink is muted, below 5%, or its volume
  cannot be read. This also overrides intentional mute and low volume. Left as-is
  because it is an existing explicit recovery policy, unrelated to this crash.
- **Legacy configurations:** root `configuration.nix`, `.dotfiles/`, and
  `legacy/home/` are not imported by the active root flake. The root legacy config
  enables both GDM and greetd and references the external disks; it should not be
  used to recover the internal installation. `/etc/nixos` is a symlink to this repo,
  not a separate active configuration.
- **Nonfatal evaluation warnings:** upstream `stdenv.isLinux`/`isDarwin` deprecations,
  the `nixfmt-rfc-style` alias deprecation, and Home Manager's Firefox profile-location
  warning remain. Firefox retains its
  existing location under the pinned home state version; no migration was made.
- **Hardware log noise:** ACPI, ELAN touch device, and USB-C controller errors also
  occur on the recovered boot. They are separate from the filesystem timeout
  sequence; this audit does not establish fixes for those hardware/driver issues.
- **Capacity and services:** root filesystem had 352 GiB available; ESP had 183 MiB
  available; recovered swap was about 17 GiB. No failed system or user units were
  listed when inspected. This incident was not a full-disk build failure.

## Validation

- Read all system and Home Manager modules, both hosts, auxiliary desktop files,
  and the legacy configuration copies. All 39 Nix files passed syntax parsing.
- Successfully built both complete NixOS systems, including Home Manager, with
  `nix build --no-link --no-write-lock-file` and the existing lock file.
- `nix flake check --no-build --no-write-lock-file` passed for both hosts and the formatter.
- Executed only the generated pre-switch scripts: the internal configuration
  passed and the external configuration was rejected for each of `switch`, `test`,
  `boot`, and `dry-activate`. No system activation was performed.
- Verified the built ESP permissions and masked speech-dispatcher socket.
- Niri validation, WezTerm configuration loading, shell/Python syntax checks,
  strict JSON/lock-file parsing, and `git diff --check` passed.

The pre-existing edits in `home/niri/config.kdl` and `home/wezterm.lua` were preserved.
No dependencies were updated, generations deleted, commits made, or system switched.

## Apply the verified internal configuration

Run in your own terminal (sudo needs your password):

```sh
sudo nixos-rebuild switch --flake ~/nixos-config#xelo-nixos-main
```

Then `bootctl status` should show the new internal generation as default. Future
rebuilds can use `rebuild`; use `rebuild-check` for a build without activation.
If you must reboot before applying this, select the known-good generation 109 again.

Reference: [NixOS rebuild documentation](https://wiki.nixos.org/wiki/Nixos-rebuild).
